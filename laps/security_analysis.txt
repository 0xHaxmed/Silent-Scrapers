# تحليل أمني للابات الأربعة - Zero Team
# =====================================

## Lab 1 - نظام Zero Team (نظام إدارة الموظفين)
### =======================================

#### وصف النظام:
- نظام إدارة للموظفين في شركة Zero Team
- يحتوي على مدير وموظفين
- يمكن رفع الملفات والمشاريع
- نظام تسجيل دخول للموظفين

#### الثغرات المكتشفة:
1. ثغرة رفع الملفات (File Upload Vulnerability)
   - لا يوجد تحقق من نوع الملف المرفوع
   - يمكن رفع ملفات PHP ضارة
   - لا يوجد تحقق من حجم الملف
   - يمكن استغلال basename() للتحايل على الأمان

2. ثغرة تسجيل الدخول (Authentication Vulnerability)
   - كلمات المرور مخزنة بشكل نصي (plain text)
   - لا يوجد حماية ضد هجمات Brute Force
   - لا يوجد حد لعدد محاولات تسجيل الدخول

3. ثغرة التحكم في الوصول (Access Control)
   - التحقق من صلاحيات المستخدم يتم بشكل بسيط
   - يمكن التلاعب بـ $_SESSION['user_name']
   - يمكن للموظف العادي الوصول لصلاحيات المدير

#### كيفية استغلال الثغرات:
1. استغلال رفع الملفات:
   - رفع ملف PHP ضار يحتوي على shell
   - تنفيذ أوامر على السيرفر
   - الوصول إلى نظام الملفات
   - سرقة ملفات المشاريع

2. استغلال تسجيل الدخول:
   - استخدام قوائم كلمات مرور معروفة
   - هجمات Brute Force على حسابات الموظفين
   - التلاعب بالجلسات للوصول لحساب المدير

3. استغلال التحكم في الوصول:
   - تعديل قيمة $_SESSION
   - الوصول إلى صلاحيات المدير
   - تعديل بيانات الموظفين الآخرين

#### كيفية الحماية:
1. حماية رفع الملفات:
   - التحقق من نوع الملف
   - تحديد حجم أقصى للملفات
   - تغيير أسماء الملفات
   - استخدام whitelist للملفات المسموح بها

2. حماية تسجيل الدخول:
   - تشفير كلمات المرور
   - إضافة حماية ضد Brute Force
   - استخدام CSRF tokens
   - تسجيل محاولات تسجيل الدخول

3. حماية التحكم في الوصول:
   - التحقق الآمن من الصلاحيات
   - استخدام نظام أدوار متكامل
   - تسجيل العمليات الحساسة

## Lab 2 - نظام الجريدة
### =================

#### وصف النظام:
- نظام إدارة محتوى للجريدة
- نشر المقالات والأخبار
- نظام تعليقات
- إدارة المحررين والكتاب

#### الثغرات المكتشفة:
1. ثغرة SQL Injection
   - عدم استخدام Prepared Statements
   - عدم تنظيف المدخلات
   - عرض رسائل الخطأ للمستخدم
   - يمكن تعديل المقالات

2. ثغرة XSS (Cross-Site Scripting)
   - عدم تنظيف المخرجات في التعليقات
   - عدم استخدام htmlspecialchars()
   - تخزين وتنفيذ سكربتات ضارة
   - يمكن حقن كود في المقالات

3. ثغرة CSRF (Cross-Site Request Forgery)
   - عدم استخدام CSRF tokens
   - عدم التحقق من مصدر الطلبات
   - يمكن نشر محتوى ضار

#### كيفية استغلال الثغرات:
1. استغلال SQL Injection:
   - حقن أوامر SQL
   - استخراج بيانات المستخدمين
   - تعديل المقالات
   - سرقة بيانات المحررين

2. استغلال XSS:
   - حقن سكربتات JavaScript في التعليقات
   - سرقة الكوكيز
   - تنفيذ هجمات على القراء
   - تعديل محتوى المقالات

3. استغلال CSRF:
   - نشر محتوى ضار
   - تعديل بيانات المستخدمين
   - سرقة الجلسات

#### كيفية الحماية:
1. حماية SQL Injection:
   - استخدام Prepared Statements
   - تنظيف المدخلات
   - إخفاء رسائل الخطأ

2. حماية XSS:
   - تنظيف المخرجات
   - استخدام htmlspecialchars()
   - تطبيق Content Security Policy

3. حماية CSRF:
   - استخدام CSRF tokens
   - التحقق من مصدر الطلبات
   - استخدام SameSite cookies

## Lab 3 - متجر نون الإلكتروني
### =========================

#### وصف النظام:
- متجر إلكتروني متكامل
- نظام سلة المشتريات
- نظام الدفع
- إدارة المنتجات والمخزون

#### الثغرات المكتشفة:
1. ثغرة Local File Inclusion (LFI)
   - عدم التحقق من مسارات الملفات
   - عرض محتوى ملفات النظام
   - يمكن الوصول لبيانات العملاء

2. ثغرة Remote File Inclusion (RFI)
   - تحميل ملفات من مصادر خارجية
   - تنفيذ كود ضار
   - يمكن تعديل أسعار المنتجات

3. ثغرة Command Injection
   - تنفيذ أوامر النظام
   - عدم تنظيف المدخلات
   - يمكن تعديل المخزون

#### كيفية استغلال الثغرات:
1. استغلال LFI:
   - قراءة ملفات النظام
   - الوصول إلى بيانات العملاء
   - عرض كود المصدر
   - سرقة معلومات الدفع

2. استغلال RFI:
   - تحميل سكربتات ضارة
   - إنشاء backdoor
   - تعديل أسعار المنتجات
   - سرقة بيانات البطاقات

3. استغلال Command Injection:
   - تنفيذ أوامر النظام
   - الوصول إلى shell
   - تعديل المخزون
   - سرقة بيانات العملاء

#### كيفية الحماية:
1. حماية LFI:
   - التحقق من المسارات
   - تقييد الوصول للملفات
   - استخدام whitelist

2. حماية RFI:
   - تعطيل allow_url_include
   - التحقق من المصادر
   - تقييد الوصول

3. حماية Command Injection:
   - تنظيف المدخلات
   - استخدام whitelist للأوامر
   - تقييد الصلاحيات

## Lab 4 - نظام حجز التذاكر
### =====================

#### وصف النظام:
- نظام حجز تذاكر متكامل
- إدارة الحجوزات
- نظام الدفع
- إدارة المستخدمين

#### الثغرات المكتشفة:
1. ثغرة Session Hijacking
   - عدم تجديد معرفات الجلسات
   - عدم التحقق من IP
   - تخزين معلومات حساسة في الجلسة
   - يمكن سرقة الحجوزات

2. ثغرة File Upload
   - رفع ملفات ضارة
   - تنفيذ كود PHP
   - الوصول إلى shell
   - يمكن تعديل بيانات الحجوزات

3. ثغرة Privilege Escalation
   - تجاوز صلاحيات المستخدم
   - الوصول إلى وظائف المدير
   - تعديل البيانات الحساسة
   - يمكن تعديل الحجوزات

#### كيفية استغلال الثغرات:
1. استغلال Session Hijacking:
   - سرقة معرفات الجلسات
   - انتحال هوية المستخدمين
   - الوصول إلى حسابات الآخرين
   - سرقة الحجوزات

2. استغلال File Upload:
   - رفع webshell
   - تنفيذ أوامر النظام
   - السيطرة على السيرفر
   - تعديل بيانات الحجوزات

3. استغلال Privilege Escalation:
   - تعديل صلاحيات المستخدم
   - الوصول إلى وظائف المدير
   - تعديل البيانات الحساسة
   - سرقة بيانات الدفع

#### كيفية الحماية:
1. حماية Session Hijacking:
   - تجديد معرفات الجلسات
   - التحقق من IP
   - تشفير بيانات الجلسة

2. حماية File Upload:
   - التحقق من نوع الملف
   - تغيير أسماء الملفات
   - تقييد الصلاحيات

3. حماية Privilege Escalation:
   - التحقق الآمن من الصلاحيات
   - تسجيل العمليات الحساسة
   - فصل الصلاحيات
